1. System Overview

Lemonn is a comprehensive multi-asset trading platform enabling users to trade:

  • Indian Equities - NSE/BSE stocks (Delivery, Margin, Intraday)
  • Derivatives (FnO) - Futures & Options with Greeks calculation
  • Mutual Funds - SIP & lumpsum investments
  • US Stocks - International equity trading
  • Fixed Deposits - FD investments
  • Cryptocurrency - Crypto trading (via Coinswitch integration)

🎯 Platform Capabilities

  • Real-time Trading with WebSocket-based price feeds
  • Advanced Charting - ScalpPro with 45+ technical indicators
  • Strategy Execution - Automated trading based on ML signals
  • TPSL Orders - Take Profit / Stop Loss with one-cancels-other logic
  • GTT Orders - Good Till Triggered persistent orders
  • Underlying Derivative Orders (UDO) - Place limit orders on spot, execute on derivatives
  • Multi-broker Support - Vendor adapter pattern (NOS architecture)
  • Comprehensive KYC - Digio integration with AML checks
  • Referral System - DRA (Digital Relationship Agent) affiliate program

6. Ledger & Balance Tracking System

📊 Ledger as Single Source of Truth

The Payment Service maintains an immutable transaction ledger using double-entry bookkeeping. Every financial event (deposit, withdrawal, trade, charge) creates a ledger entry with debit/credit accounts.

Ledger Entry Structure

Table: transaction_ledger transaction_id | UUID (primary key, unique) client_id | VARCHAR (indexed) user_id | UUID (indexed) transaction_type | ENUM (DEPOSIT, WITHDRAWAL, TRADING_BUY, TRADING_SELL, | BROKERAGE_CHARGE, STT_TAX, DIVIDEND, INTEREST) amount | DECIMAL(15,2) (precise to 2 decimal places) debit_account | VARCHAR (account identifier being debited) credit_account | VARCHAR (account identifier being credited) gateway_reference | VARCHAR (payment gateway txn ID) broker_reference | VARCHAR (broker trade ID) status | ENUM (PENDING, COMPLETED, FAILED, REVERSED) timestamp | TIMESTAMPTZ (created at) completed_at | TIMESTAMPTZ (when status = COMPLETED) metadata | JSONB (fee breakdown, notes, extra details)

Balance Calculation Logic

FREE BALANCE CALCULATION: Free Balance = SUM(Completed Deposits) - SUM(Completed Withdrawals) + Realized P&L from Sold Positions - Unrealized Losses (for margin calculation) - Brokerage & Tax Charges - Margin Blocked by Open Orders Example: Initial Deposit: ₹100,000 Withdrawal: -₹10,000 Trade Profit (sold): +₹5,000 Brokerage Charges: -₹200 Open Order (blocked): -₹20,000 ──────────────────────────────── Free Balance: ₹74,800 MARGIN CALCULATION: Available Margin = Free Balance × Margin Multiplier Margin Multiplier by Product Type: • DELIVERY (Cash): 1x (no leverage) • MARGIN (MF): 3x (3:1 leverage) • INTRADAY (MIS): 5x (5:1 leverage) • F&O (Derivatives): Variable (based on volatility) Example: Free Balance: ₹74,800 Product: MARGIN (3x) Available Margin: ₹224,400 BUY POWER CALCULATION: Buy Power = Available Margin + Collateral Value Collateral Sources: • Pledged holdings (stocks) • Mutual fund units • Fixed deposits • Govt bonds Example: Available Margin: ₹224,400 Pledged RELIANCE: +₹50,000 ──────────────────────────────── Total Buy Power: ₹274,400

8. Trading Flow (Spot & FnO)

Spot Equity Trading

ORDER LIFECYCLE: 1. PRE-TRADE PREPARATION ├─ Get holdings: Vault → Holdings table ├─ Get live price: Markets Middleware → Redis cache ├─ Calculate margin: Payment Service → marginInfo API ├─ Check market status: NFS → NSE/BSE timings └─ Fetch collateral: Vault → pledged holdings 2. ORDER PLACEMENT ├─ Frontend validation (qty, price, lot size) ├─ GraphQL mutation: ieTradePlaceOrder ├─ Transformer → Backend broker API ├─ Backend checks: │ ├─ Margin availability (50k required for 100 shares @ 500) │ ├─ Circuit limits (5% upper/lower) │ ├─ AML/Fraud flags │ └─ Position limits (max 10% of total capital in one stock) ├─ OrderBook INSERT (Status: PENDING) └─ Broker API call (NSE/BSE) 3. BROKER PROCESSING ├─ Pre-trade risk checks ├─ Order matching against exchange orderbook ├─ Execution (full or partial fill) └─ Trade confirmation sent back 4. POST-EXECUTION ├─ OrderBook UPDATE (Status: EXECUTED, AvgPrice: 499.50) ├─ Holdings INSERT (if DELIVERY): │ ClientID: CLI789 │ Symbol: RELIANCE │ TotalAvailable: 100 │ BuyAvgPrice: 499.50 │ T1Qty: 100 (T+1 settlement) │ FreeQty: 0 (available after T+2) ├─ Positions INSERT (if INTRADAY): │ BuyQty: 100, BuyAvgPrice: 499.50 │ SellQty: 0 │ UnrealizedPnL: (LTP - 499.50) * 100 └─ Real-time WebSocket update to Flutter 5. INTRADAY P&L TRACKING ├─ Live price feed from market data (every 1 sec) ├─ Positions table updated with current LTP ├─ P&L = (LTP - AvgPrice) * Qty ├─ Example: │ Buy: 100 @ 499.50 │ LTP: 505.00 │ P&L: (505 - 499.50) * 100 = +₹550 └─ Displayed in real-time in portfolio 6. SETTLEMENT (T+2 for equity) ├─ T+0: Order executed, position created ├─ T+1: Move to T1Qty (shares in transit) ├─ T+2: Final settlement, move to FreeQty └─ Now available for selling or pledging 7. EXIT/SQUARE OFF ├─ User places SELL order ├─ FIFO matching (from buy_fifo array) ├─ Cost basis calculation (for tax reporting) ├─ Realized P&L computed ├─ Ledger entry: TRADING_SELL └─ Holdings updated (qty reduced)

Derivatives (FnO) Trading

F&O DIFFERENCES FROM SPOT: • ProductType: 'D' (Derivative) instead of 'M'/'I' • Token-based: Uses numeric token, not symbol string • Strike & Expiry: Tracks strike price + expiry date • Greeks: Delta, Gamma, Theta, Vega calculated • Margin: Higher multiplier (2-5x depending on volatility) • Lot Size: Fixed lot size (e.g., NIFTY = 50 shares/lot) • Settlement: T+1 only (faster than equity) • Mark-to-Market: Daily M2M losses/gains EXAMPLE ORDER: Symbol: NIFTY24MAY24000CE ├─ Underlying: NIFTY 50 Index ├─ Expiry: 2024-05-30 ├─ Type: CALL option ├─ Strike: 24,000 ├─ Lot Size: 50 ├─ Premium: ₹150 per share └─ Total Cost: 150 * 50 = ₹7,500 (for 1 lot) Greeks Displayed: • Delta: 0.65 (65% correlation with underlying) • Gamma: 0.02 (rate of change of delta) • Theta: -50 (loses ₹50/day due to time decay) • Vega: 15 (₹15 change per 1% IV change) • IV: 18% (Implied Volatility)

TPSL (Take Profit / Stop Loss) Orders

TPSL ORDER STRUCTURE: Parent Order (Main Buy/Sell): OrderID: ORD001 Symbol: RELIANCE Qty: 100 Price: 500 Status: EXECUTED TPSLGroupID: GRP123 ↓ Child Orders (Linked via TPSLGroupID): ├─ Take Profit Order: │ OrderID: ORD002 │ Symbol: RELIANCE │ Qty: 100 │ TriggerPrice: 550 (10% profit target) │ OrderType: LIMIT │ OrderCategory: TP │ TPSLGroupID: GRP123 │ Status: OPEN │ └─ Stop Loss Order: OrderID: ORD003 Symbol: RELIANCE Qty: 100 TriggerPrice: 480 (4% max loss) OrderType: MARKET (immediate sell) OrderCategory: SL TPSLGroupID: GRP123 Status: OPEN EXECUTION LOGIC: If LTP hits 550: ├─ TP order (ORD002) triggers ├─ Sells 100 RELIANCE @ market ├─ ORD002 Status: EXECUTED ├─ ORD003 (SL) Status: CANCELLED (one-cancels-other) └─ Realized P&L: (550 - 500) * 100 = +₹5,000 If LTP drops to 480: ├─ SL order (ORD003) triggers ├─ Sells 100 RELIANCE @ market (immediately) ├─ ORD003 Status: EXECUTED ├─ ORD002 (TP) Status: CANCELLED └─ Realized Loss: (480 - 500) * 100 = -₹2,000 TRAILING STOP LOSS: • SL adjusts upward as price rises • Locks in profits while allowing upside • Example: Buy @ 500, T-SL @ -5% ├─ If LTP = 550 → SL moves to 522.50 (550 * 0.95) ├─ If LTP = 600 → SL moves to 570 (600 * 0.95) └─ Protects ₹70 profit even if price drops

12. Security & Compliance

Security Measures

🔐 Authentication & Authorization

  • JWT Tokens: RS256 signed with private key, 1-hour expiry
  • Refresh Tokens: 30-day validity, stored in Redis with revocation support
  • MFA: Optional two-factor authentication via OTP
  • Session Management: Redis-backed sessions with auto-expiry
  • Device Fingerprinting: x-device-id tracking for suspicious activity

🛡️ KYC (Know Your Customer)

  • Digio Integration: Aadhaar-based eKYC verification
  • Document Upload: PAN card, bank statement, address proof → S3 storage
  • Status Tracking: PENDING → IN_PROGRESS → COMPLETED → VERIFIED
  • KYC Refresh: Periodic re-verification (every 2 years)
  • Lambda Processing: Async KYC event handling
  • Withdrawal Restriction: Only FULL_KYC users can withdraw funds

💰 AML (Anti-Money Laundering)

  • AML Pipeline: US ID Service Lambda functions
  • Screening: Name match against OFAC, UN sanctions lists
  • Transaction Monitoring: Large transactions flagged for review
  • Suspicious Activity: Auto-flagging based on patterns (rapid deposits/withdrawals)
  • Manual Review: Compliance team approval required for flagged accounts

Risk Management

Risk Type Mitigation Strategy
Circuit Breakers Trading halted at 5%, 10%, 20% volatility thresholds (set by exchange). Market status checked before every order.
Position Limits Max 10% of total capital in single stock. Max 20% in single sector. Enforced at order validation.
Margin Monitoring Real-time margin utilization tracking. Square-off triggered if margin drops below 50%. Email/SMS alerts at 70%, 60%, 50%.
Surveillance Flags Exchange surveillance system flags suspicious trading. Users locked out immediately. Manual review required for unlock.
Order Throttling Max 100 orders per minute per user. Prevents algo abuse and fat-finger errors.

Data Security

🔒 Encryption & Storage

  • At Rest: PostgreSQL encrypted volumes (AES-256)
  • In Transit: TLS 1.3 for all API communication
  • Passwords: Bcrypt hashing with salt (cost factor: 12)
  • Sensitive Data: PII sanitization in logs (Transformer middleware)
  • Secrets: AWS Secrets Manager for API keys, DB credentials
  • Client-side: Flutter Secure Storage (OS keychain encryption)
