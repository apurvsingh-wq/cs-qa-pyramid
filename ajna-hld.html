🧠 What is Ajna

Ajna is CoinSwitch's AI background agent that takes work from Slack or GitHub, classifies intent, picks a persona, pulls context from the codebase, and runs an AI coding agent that produces PRs, reports, ADRs, and incident triage — autonomously.


TriggerWhat happensOutput
@ajna in SlackClassifies intent, picks persona, runs BrainSlack reply / PR / report
/ajna slash commandModal with repo/description, queued as feature requestPR via Claude Code in container
GitHub issue labeled ajnaWebhook triggers queue, container spins up agentPR with commits on branch
Alert in on-call channelChannel watcher parses, Brain investigates via NR/PDTriage report in Slack thread
Web UISvelteKit dashboard for config, history, statusTask tracking & setup

🔀 Data Flow

Slack/GitHub → PR (Production Path)

  1. Trigger arrives (Slack slash command / GitHub issue webhook / Web UI)
  2. Worker validates auth, creates feature_request row (status: queued)
  3. Worker enqueues message to issue-processing-queue
  4. Queue consumer picks up, routes via AgentRouter (labels determine strategy)
  5. Container DO spins up: git clone, checkout branch, load skill
  6. Agent (Claude Code SDK / OpenCode) executes with full repo context
  7. Agent commits, pushes, creates PR on GitHub
  8. Session blob (gzip) saved to agent_sessions for resumption
  9. Status + PR link posted back to Slack thread
  10. User can click "Suggest More Changes" for follow-up iterations

On-Call Triage (Legacy Server Path)

  1. Bot message arrives in alert channel (PagerDuty / New Relic / Grafana)
  2. Channel watcher filters: must be bot, not Ajna's own message
  3. Alert parser normalizes → AlertEvent { source, severity, title, service }
  4. Dedup check (5-min TTL hash) — skip if duplicate
  5. Throttle check (max 3 concurrent) — queue if at limit
  6. Brain.process() with persona=on-call:
     a. Query NR violations, error traces, deployments
     b. Query Grafana alerts, metrics (if configured)
     c. Query PagerDuty incident detail, on-call schedule (if configured)
     d. Search codebase via EFS for related files
  7. Structured triage report posted to Slack thread

🚨 On-Call Agent (Latest Build)

The on-call module watches a Slack channel for production alerts from PagerDuty, New Relic, and Grafana. It parses, deduplicates, investigates using MCP tools, and posts structured triage reports.

Components Built

  • Alert parser (PD/NR/Grafana → AlertEvent)
  • Alert dedup (5-min TTL, SHA-256 hash)
  • Alert storm throttle (max 3 concurrent)
  • Channel watcher + bot wiring

  • Grafana MCP (query, alerts, dashboard)
  • PagerDuty MCP (incident, on-call, ack, resolve)
  • Toolshed registration + prerequisites
  • Brain tool execution wiring
  • Enhanced on-call skill prompt
  • /ajna-test-alert command for e2e testing

🛠 Getting Started

Prerequisites

Node 22+, npm, wrangler CLI, PostgreSQL (local or remote)

Clone & Install

git clone <repo-url> && cd ajna
npm install
cd frontend && npm install && cd ..
cd container_src && npm install && cd ..

Run the Legacy Server (fastest for local dev)

# Copy .env.example to .env and fill in your keys
cp .env.example .env

# Load env and start
set -a && source .env && set +a
npm run dev          # Express on :3000 with Slack socket mode

Run the Cloudflare Worker

npx wrangler dev     # local CF Workers runtime
npx wrangler deploy  # deploy to production

Run the Frontend

cd frontend
npm run dev          # Vite dev server

Database

# Schema lives at src/db/schema.ts
npm run db:generate  # generate migration SQL
npm run db:migrate   # apply to PostgreSQL

Tests

npm test                                    # all tests
npx vitest run tests/oncall/               # on-call module only
cd container_src && npm test               # container tests
